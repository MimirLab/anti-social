### Data briefs and complete roundup links (0.35.25)

Context's primary output is one concise prose brief of the post and its linked
material. Comments supplement that brief only with useful information; reactions,
feelings, bickering and lists of who agrees or disagrees are not its purpose.
Evidence and original quotations are expandable. This replaces 0.35.24's
finding-first default, which exposed the intermediate ledger instead of doing
the reader's synthesis work.

Link collection and cleanup use deterministic code. Fresh parsed posts retain up
to 256 destinations instead of the former global 12-link cap. Complete URLs in
an original cached heading can recover destinations missing from its attachment
list; shortened labels are never guessed into fetch URLs. Labelled roundup lists
fold beneath their introduction while exact source characters remain recoverable.
Nitter RSS caption echoes with shortened labels are compared against the full
heading's destinations in order before the duplicate heading is omitted. The
native link inventory and Context share the recovered, authentic destinations.

A linked social permalink contributes only the exact requested post, not replies
or neighbouring posts returned on the same page. Direct post links are acquired
before comment streams. Complete, prepared English linked-source text of at most
480 characters is retained intact for the combined summary, without spending a
separate generation on a paraphrase. Partial, unconfirmed-language and comment
sources retain their own review path. One unavailable or deferred comment cannot
veto a useful brief from the material already read. Longer material still uses
the counted, resumable extraction and compaction hierarchy.

Posting timestamps stay in native evidence and receipt identity, outside the
reader-brief prompt; a posting date is not an event date. A narrow mechanical
check can reject newly introduced capitalized multiword/compound names absent
from the supplied text, author names and reply context, as well as explicit
acronym definitions absent from that material. A completed response can
be rewritten once against the same source evidence. This is not general
entailment validation or a guarantee of model accuracy. Ambiguous transport
failures are not repeated as inference requests.

The brief and its citations are published together. Arrivals wait behind Updates
ready, an earlier publication has one bounded local slot, and explicitly saved
snapshots remain protected. Database version seven migrates version six without
replacing source records, subscriptions, settings or saved captures; the extra
publication participates in cache byte accounting and owner cleanup.

Qualification distinguishes linked-post text from video understanding. Reading
a post that describes a summit talk does not establish that the talk's audio or
video was transcribed. Available captions, transcripts and recognized image text
have their separate evidence paths and coverage. No source availability or
physical-phone speed guarantee follows from the laptop/server observations.

### Guard source reviews while inference waits (0.35.17)

A fresh publication snapshot cannot repair a stale source classification. The
reader now reserves a bounded review window after English preparation. One
SQLite transaction verifies the original source projection, checked English
body/title/legacy reading input, complete typed post/parent background, merged
snapshot revision and processing policy against what the engine will receive.
Fresh resolver objects share parent sources within that window. No language
model, translation, detection or network operation runs inside this transaction.

At most eight prepared sources receive local random tokens. Source/alias edits,
changed reading views, imported known findings, media invalidation and owner

findings as well as its explicit parent. Snapshot/policy changes revoke old tokens

progress messages, saving and scheduling choices preserve current work. Completed

Each unit commit atomically checks its token in the same transaction as its
receipt/projection write. The completed-source marker requires the token too,
closing an edit between the last unit and completion. A revoked result, including
NO_SIGNAL, stays pending and cannot resurrect evidence removed by an edit. The
reader queues another check while leaving the earlier publication and saved copy
readable. Finally/cancellation cleanup removes only matching tokens, so an older
job cannot delete a newer window. A subsequent window supersedes abandoned tokens.
Valid completed units retain the existing cancellation-safe checkpoint behavior.

Checked English views are also interpretation inputs. Installing a changed view

### Review parent sources before their replies (0.35.16)

Acquisition order is not conversation order. The engine now orders supplied,
explicit source dependencies before reviewing children. The Android controller
resolves indexed parent aliases across the entire owner, then orders pending
sources before applying its work limit. A parent outside the first eight pending
rows therefore cannot leave its earlier-arriving short answer exposed to a
premature relevance decision. Ambiguous aliases remain unresolved even if only
one candidate is pending. Already-completed or absent parents do not invent new
pending work. The merged post participates through its explicit local source ID.

The stable dependency order uses iterative graph traversals and strongly
connected components. Preferred order breaks ties between eligible groups; members
of a malformed cycle keep their original order, and external descendants wait
behind that group. This prevents recursive-stack overflow and infinite scheduling;
it does not certify a cyclic relationship as correct. The existing chronological
feed, displayed reading anchor and explicit publication-update action are unchanged.

Protected questions now take their existing literal-source path before any
model relevance vote. That vote could not change their admission, so a false,
malformed or unavailable vote no longer wastes work or blocks the question.
Already-retained, complete, certain questions still gate the closed-answer
shortcut; that safeguard has not been weakened. Fast deterministic work is checked
before constructing model batches. Sources with a known parent/child relationship
cannot enter the same independent extraction batch, including larger-model plans.
Other replies still receive the normal model review and source validation.

Recipe `context-source-v6.8-parent-order` reopens incompatible receipts on the next
authorized read, preserving earlier/saved views, source copies, translations and
acquisition progress. There is no schema migration, new networking, root requirement
or model/window/KV default change. Source order is scheduling, not a new relevance
score. Missing context, general semantic selection, source quality and generation
fidelity retain their existing limits.

The audit runner additionally offers an explicit development-only

### Reply meaning and local parent sources (0.35.15)

Canonical finding IDs still group repeated wording. Presentation additionally
partitions short/deictic contributions by their explicit parent frame, so two

validated literal findings (or a single already-retained paraphrase) with speaker labels and bounded parent excerpts;
it removes a separately retained question only when the complete, exact question
and all its sources are already present in an answer frame. An answer does not
establish that its claim is true. Longer self-contained contributions retain one
text block, while local source inspection can still show their parent.

For the focused extractive recipe, a small whitelist of literal closed answers
can bypass another model decision only when their exact, complete, certain parent
was already retained as a question from the actual parent source. Code quotes
what the reply said; it never invents an answer. Other replies use normal review.
The display heuristic (short text or deictic wording) is not a relevance classifier.

Publications and protected saved snapshots now carry optional `replyEvidence`:
a child-source-to-frame registry, bounded English excerpts, explicit limitations,
and distinct original parent documents not already among cited findings. Parent
aliases resolve uniquely; ambiguous or missing references stay unavailable. The
original parent is stored once per publication, not copied into every reply.
Frames use only validated, cached English readings. Missing English preparation
is marked pending; composition never downloads, translates or falls back to the
unprepared original text. The local parent viewer can display that original.

The SQLite publication snapshot and atomic admission guard include these frames
and original parent documents. Parent processing bookkeeping alone is not new
meaning. Actual parent, translation, relationship or quality changes are. Saved
views keep the captured relationship and source after later working-source edits.
The summary recipe carries bounded reply contexts through compaction and binds
them into cache identities. Small exact-source framed briefs and single framed findings have a separate
4,096-character display allowance; this is code-rendered reading text, not a

The executable recipe is `context-source-v6.7-reply-context`; the next authorized
read reopens incompatible receipts while preserving earlier/saved publications,
source pages, translations and acquisition progress. No database schema migration,

findings, including the source span, processing profile and supplied
post/reply-parent background. Re-reading a revised qualification or changed
parent cannot reuse an earlier compaction merely because its selected words
and quotations happen to be identical. Changed child receipts invalidate their
ancestors while unaffected branches remain reusable.

Only receipts supporting retained findings enter this identity. Empty tail
reviews, reaction-only comments, duplicated receipt IDs and database row order
do not themselves create new meaning. The captured publication input includes
these identities, so its atomic admission check also detects a changed review
context with unchanged child text. Retrieval-only updates and exact additional
source-copy reuse retain their existing paths.

Internal publication/saved-view JSON has an optional `reviewIdentities` map from
source ID to a local receipt-set hash. Missing legacy identities remain unknown;
the new processing recipe rebuilds incompatible work on the next authorized
read, preserving source pages, translations, cursors and earlier/saved views.
There is no schema migration; receipt-set hashes stay local. These are cache-validity
checks: they do not guarantee that extraction noticed a new qualification or
that generated prose interpreted its evidence correctly.

### Evidence changes during composition (0.35.13)

Composition now reads a consistent local snapshot of findings and their cited
sources, including author, dates, extraction scope and quality. Source labels
and interpretation metadata for every compaction level come from that same
snapshot. At publication, one SQLite transaction checks the post revision,
processing policy, reviewed findings and source evidence before pairing the
brief with its local citations. A source edit during a model request therefore
cannot attach old prose to newer source copies. The previous publication and
explicit saved view remain readable while the changed work waits for review.

Fresh retrieval times, URLs and validators can update citation provenance
without invalidating unchanged interpretation. Publication updates only the
generated fields over current reader state, preserving saving and scheduling
choices made while inference was pending. Source hydration uses queries bounded
below older Android parameter limits; no schema change, added network request
or additional model call is required. These consistency checks do not establish
the semantic accuracy of the brief or recover information a model omitted.

### Source text and bounded edition views (0.35.12)

Acquisition records now distinguish caption text, image descriptions, recognized
image/document words, speech transcripts and ordinary source text. These are
facts supplied by the app's extractors, not a model's confidence or an AI-content
detector. Recorded uncertainty, truncation and automatic recognition remain
attached through higher compaction levels. Local citation dialogs explain the
available text in plain language. Captions do not establish what happened in
silent visual steps; recognized words are not a complete image interpretation.
This metadata helps interpretation but cannot guarantee that a model respects it.

Source-type associations participate in review and composition identities even
when words are unchanged. Changing a source from captions to speech recognition
cannot silently reuse its earlier interpretation. Experimental extra narrative
guidance is disabled in production after it regressed a real 2B comparison; its
instruction mode also has a separate processing identity in the audit.

Bounded source-time frames keep the earliest known instant, latest known instant
and an undated context when present. Additional contexts have explicit known and
unknown counts, distinct instants and complete earliest/latest bounds. Counts
and ranges do not establish continuous coverage, agreement or independent
corroboration. Native previews use the same fair selection and expand all
retained editions chronologically. The full source identity is preserved even
when the model sees representatives.

For extractor-marked caption and audio sources, bracketed line-start media cues
such as `[0:08]` locate the text; they are not content quantities that every brief
must repeat. Actual quantities and times in the source's words remain subject to
the existing limited correction-preservation check. This guard is not a general
semantic verifier. No additional network request or model download is introduced.

### Source publication context (0.35.11)

Publication metadata is interpretive context. Identical wording posted on
different days may refer to different events; the exact-copy publication shortcut
therefore requires matching publication instants. Equivalent ISO offsets normalize
to the same instant. A missing or malformed date never borrows retrieval time or
another edition's timestamp. Caption text remains unchanged by the date formatter.
UTC publication labels do not establish the author's local timezone or the time
an event happened; this change does not certify model date arithmetic.

Merged records retain known and undated attribution for up to 64 editions, with
bounded 100-character names in one or two metadata chunks. Full original records
remain in the snapshot. Code feeds source times into extraction and composition,
separately from optional descriptive metadata, with explicit unavailable/earliest
edition qualifiers and a count of additional contexts omitted from a bounded
prompt. Higher compaction nodes retain the complete context identity outside
that prompt. Small exact-source overviews render readable source dates without
asking a model to calculate or paraphrase them. Local source dialogs distinguish
Posted from Retrieved/Captured and expand to show all retained edition dates.

Publication admission also checks whether earlier cited sources still await
review, including deferred failures. It retains the coherent earlier brief and
local citations until replacement reviews can finish. These status checks use
bounded SQLite queries rather than decoding source bodies. Explicit saved views
remain intact. No SQL schema change or extra acquisition request is required.

### Model changes and durable work (0.35.10)

Processing identities bind the selected model, actual input/output/decision
allowances, executable recipe and evidence/prompt/summary versions. Metadata
timestamps and explanatory reason prose do not invalidate work. The source
review and compaction IDs use this identity, and published briefs retain a
separate composition binding. Matching finding words alone cannot reuse an
overview written by another model or recipe. Older unbound publications are
recomposed once on an authorized read; matching, individually bound compaction
receipts remain reusable. Source pages, translations, stream
cursors and explicit saved snapshots survive model changes.

When rebuilding a previous brief, it remains readable with its original source
excerpts until collected documents have been reviewed successfully. Failed or
deferred reviews retain the prior publication and show the pending coverage.
A selected-model change during a job pauses it rather than attributing the old
response to the new model. A server silently replacing weights behind the same
model name cannot be identified reliably from that name alone. Changing a
setting does not itself authorize new background or remote work.

### Model response timing (0.35.9)

Inference requests have a two-minute total deadline, including quiet model
preparation before headers or between body bytes. Their socket read allowance
now matches that deadline; it previously inherited the ordinary 15-second direct
or 45-second Tor website timeout. Cancellation still closes the request. Model
metadata and ordinary content retain their existing shorter budgets, and no
provider fallback or automatic retry is introduced. The larger allowance does
not turn an output-token-limit response into a completed answer.

### Additional source copies (0.35.8)

An extra complete, identical source can update the published source manifest
without another overview generation. The app checks the full document, its
parent/background, extraction-quality metadata, original quotation and any
English working quotation. All earlier supporting documents must remain
unchanged. Matching generated finding words alone are insufficient. Each added
author and source retains its own native citation and original link; identical
copies are not declared independent confirmation. Changed evidence continues
through ordinary processing and composition. This reuse rule does not certify
the interpretation in an earlier generated brief.

Context is anti social's optional evidence reader. After the reader enables AI and
selects a ready text model, it can build a brief from a post, its public comment
streams and directly attached sources. The chronological reader, subscriptions,
search, routing, saving and duplicate-merging mechanisms continue to work with
AI switched off. Darwin remains the routing donor. Stock Android needs no root,
ADB, account, Python installation or separate inference-server app for the local
model path. See [AI foundation](AI_FOUNDATION.md) for model installation and
provider choices.

This document describes the implementation and its limits. It does not certify
live source availability, universal media support, model fidelity or phone
performance. The current test files and recorded evidence distinguish fixtures,
host checks, device checks and source-dependent external behavior.

## What gets read

Context starts with the displayed post, including its merged original editions.
Each original has its own public platform discussion stream; shared discussion
uses the original post URL when that service is enabled. Sources advance by
their supplied continuation cursors and reply targets. Repeated cursors,
expired continuations, inaccessible replies, disabled services and source caps
remain visible as incomplete coverage. A failed or empty source is never
reported as a successfully read discussion.

Before fresh discussion requests, Context can reuse comment threads already
preserved in a saved copy. Only the current card's original roots and validated
captured fusion roots qualify; unrelated conversations and unattached replies
are ignored. Enabled shared discussions retain the same original-page IDs used
by their live reader. Existing cached replies, including newer edits or deletion
records, always take precedence over saved captures. These dated copies remain
separate, partial coverage: they do not establish that the live thread is current
or complete. Citations show the original capture date. Local reuse is bounded
to eight saved copies, 512 newly admitted replies and 2 MiB of document payload
per reading pass, with at most 64 captured threads examined per copy. A visible
coverage limit records omissions; least-recently-scanned roots go first on later
refreshes. Durable source IDs and receipts avoid reviewing unchanged captures
again after an interruption. Literal links in admitted saved replies follow the
same first-hop limits as live replies.

The merged post is stored once per Context record. Comment reviews refer to
that full local source and, where known, the actual reply parent. Source-native
reply identifiers and canonical public URLs can refer to the same document;
conversation membership alone does not invent an immediate parent. Reddit,
Bluesky and observed X JSON records retain their supplied relationship IDs.
Some Nitter pages establish the conversation but omit immediate parent IDs;
that missing context stays marked unavailable. Branch reads do not admit
unrelated siblings merely because they share a conversation.

The processing window determines how much background fits. The planner first
tries the complete bounded post, reply parent and source against the counted
input budget, including reserved answer space. This can retain complete
background even on a small worker. When that request cannot fit, both background
sources receive a share of a counted excerpt, with truncation and uncertainty
marked. Fallback excerpts are prefixes, so a later qualification can still be
absent from a particular small-window review. The complete local documents remain available. An explicit
missing parent prevents a model's “no signal” answer from completing the review;
there is currently no automatic network fetch solely to recover that parent.

The local dependency index reopens affected reviews when a parent is edited,
deleted, evicted or newly available. Identical short replies to different parents
are not treated as interchangeable without review. Fetch timestamps and URL-only
provenance changes do not repeat an otherwise unchanged review. Publication-date
and extraction-scope changes are interpretive context and do reopen affected
work. Earlier published briefs and cited source
copies remain readable while changed work is pending. The database migration
preserves existing saved copies and processing receipts.

Acquisition is controlled by app code. Literal HTTPS links supplied by the post
or its comments may create a first-hop source stream. Recognized profiles,
communities and tags, and common login/privacy/terms paths, are excluded. Pages
discovered inside those articles are not recursively crawled. Comment-derived
pages have a per-card allowance: **24 by default**, adjustable from **0 to 128**
in advanced Context settings. Reaching it produces a visible coverage limit;
the source comments and their links remain available. Post-attached links are
outside that comment allowance. Comment classification does not decide which
of these source URLs are acquired.

| Evidence | Current behavior and limits |
| --- | --- |
| Public social post or discussion | Uses the existing source pool and permitted accountless original fallback. Actual bodies, replies and pagination depend on each source. A login wall is not working content. |
| Ordinary article | Fetches HTML through the gateway, then extracts readable content locally with Jsoup and Readability4J. Retains headings, body, attribution and source URLs. Runs no page JavaScript and loads no page resources. Script-only pages, access challenges, short/empty bodies and unsupported formats can remain unavailable. |
| Article refresh | Reuses stored ETag/Last-Modified validators when supplied. Conditional reads pin the retrieval origin; a successful 304 retains the existing local document without another model review. |
| Linked YouTube video | Tries existing public alternate metadata/caption routes before an allowed original route. Prefers published timed captions, retaining language, timestamps and automatic-caption attribution. This supports linked video evidence; it does not turn anti social into an omni-video service. |
| Captionless video or audio | Optional local speech processing can begin after accessible video records explicitly report no captions. A blocked or broken caption endpoint does not establish caption absence. Audio must be publicly obtainable, finite and decodable on the device. Live/DRM content, unavailable audio routes and unsupported codecs remain limited. |
| Image | Keeps source-supplied descriptions where present. Optional OCR can add recognized text, language, uncertainty and the source-file hash. It does not describe all visual meaning or establish whether an image is authentic. |
| PDF | Processes one page at a time. Android 15/API 35 and later can expose embedded PDF text. Other pages and older Android versions need the enabled OCR tool. Encrypted, malformed, inaccessible or excessively large files may remain unreadable. |

Article and caption text have bounded extraction windows (currently 240,000
characters; captions also cap at 12,000 cues). Truncation is recorded as limited
coverage. Temporary audio downloads are bounded to 64 MiB and PDF downloads to
32 MiB, also subject to available cache and storage. These are processing
limits, not promises that a source will provide a usable download.

Optional media tools run on supported 64-bit ARM or x86_64 devices in a private
media worker. The first requested Context read containing images prepares the
small English Tesseract fast language pack if image reading has never been
configured. This uses NetworkGateway and the signed catalog; background work
and ordinary scrolling never initiate the download. An explicit off choice is
respected, failed setup has a fifteen-minute retry floor, and language packs
remain removable in settings. The
speech pack uses multilingual Whisper base Q5_1 with Silero voice detection.
Downloads are signed-catalog, size and hash checked, data-only packs. Opening
settings or language choices downloads nothing. CPU admission checks available
memory and thermal state. Android decodes/resamples local audio to 16 kHz mono
PCM; speech is processed in resumable two-minute slices with source timestamps.
OCR and speech output can contain errors, including omissions, and retain
uncertainty metadata. Neither is a visual truth or AI-image detector.

Short image text is harvested intact by code before one usefulness review. Names
on separate lines stay with that image's details; they are not independent
disposable findings. Images retain their actual original publication roots,
including when a collected gallery also contains separately published pictures.
Image-only inventories are read before initial composition, avoiding repeated
rewrites after each individual picture. Known retained video-frontend links are
canonicalized before acquisition so captions use the video reader rather than a
generic article extract of the frontend's menus and recommendations.

## Offline source languages

Before a text or embedding model reads newly acquired material, Context builds
an English reading view with purpose-built local language tools. The original
post, comment, article, caption or extracted text stays intact. Sentence-sized
passages are detected independently; a parent's language cannot override a
confidently different reply. URLs, code and numeric values with common units
are protected and checked after translation. Unknown languages, missing packs,
changed protected values and unverifiable translations retain the affected original
fragment with unconfirmed-language metadata. Successful neighboring translations
remain. The selected model receives the best available text; a language-confidence
check cannot silently remove an entire discussion.

Numeric arguments remain visible to the translator so it can preserve sentence
grammar. A separate ordered value/unit manifest checks them afterward; approximate
HTML word alignment is not numeric evidence. Code and URLs remain opaque and
must return unchanged. An uncertain short Japanese label can use a distinctive
kana/Han script check; shared Han alone or a quoted character cannot invent its
language. English output from a verified translation direction has a bounded
relative-confidence check for short phrases; unknown-source detection retains
its stricter rule. Numeric formatting changes that cannot be verified are rejected; best-effort
reading keeps the original values rather than guessing equivalence.

The bundled compressed fastText detector is about 938 kB. A signed catalog
currently describes 57 stable Mozilla Android-to-English directions, downloaded
separately through `NetworkGateway`. Automatic downloads require an unmetered
connection, admit at most two new languages per reading session and share a
bounded local allowance. Explicit downloads are protected until removal;
unused automatic packs expire. Detection and translation upload no source text.
Tor selection still fails closed for downloads.

The private CPU worker holds one translation direction at a time. It releases
the selected text worker before translation and releases translation state
before text inference resumes. This is ordinary unrooted Android service/JNI
code, with no Google services, external server or user-installed interpreter
required. Model packs are verified data, not executable downloads.

Each validated translation passage is checkpointed before a cancellation or
automatic-work allowance stops the job. Resume can reuse those passages, and a
complete reading view replaces its partial checkpoints. Views and findings
remain tied to source revisions and translation recipes. English model quotes
map back to complete original passages; word-for-word cross-language alignment
is not fabricated. Original quotations remain the citation evidence. Translation
quality is distinct from a text model's ability to interpret that evidence.

The 0.35.5 preview passed the recorded core and isolated Android qualification,
including actual offline Bonsai 2B/4B checks and interrupted/reopened translation
cache reuse. The laptop preview was upgraded with its stored files preserved.
Physical ARM speed, memory pressure and thermal behavior are not established by
x86_64 emulator checks. Experimental alternative engines remain research candidates;
see [the translation evaluation](CONTEXT_EVALUATION.md#translation-research-beyond-the-usual-shortlist--2026-10-19).

## Models have no acquisition authority

Models receive bounded evidence text and return structured proposed findings or
brief prose. They receive no browser, socket, shell, file-management, URL-opening,
subscription or posting tools. No generated URL or instruction becomes a fetch.
The app decides source order, network policy, concurrency, continuation, storage,
cancellation and processing allowance independently of model output. At most
two Context network exchanges run through the shared gateway concurrently; the
controller serializes Context processing jobs.

Each proposed finding must quote an exact passage from the current local source
unit. Unsupported source IDs, invented quotes, malformed output and invalid
repetition references remain retryable work. Comment units can explicitly
contain no new signal. Nonempty post/article units require a usable finding.
This validation supports attribution and persistence; an exact quote alone does
not prove that generated interpretation is correct.

Device Context requests use a fresh native JSON-object grammar, followed by
strict JSON parsing and the same finding/quote checks. Output that stops before
completing the object is an error; the app does not repair it by guessing missing
punctuation or content. This constraint controls syntax, not relevance, factual
accuracy or adherence to the requested schema. Other text utilities retain
their ordinary free-form mode. Remote Context responses undergo the same core
validation, without assuming that a provider offers native constrained decoding.

Small-model qualification has exposed semantic limits even when JSON and exact
quotes are valid: a repeated idea may be classified as new information, and
irrelevant popularity claims or insults may be treated as useful context. A
larger local choice does not guarantee that these errors disappear. Source
quotes remain inspectable; Context is optional assistance rather than a
replacement for the ordinary source reader.

The installed local English embedding companion can help choose a small set of
earlier findings to compare against a new unit. This is an optional RAM-only bank
of at most 256 vectors, scoped to embedding identity. It makes no remote
embedding requests and downloads nothing. If the companion or suitable English
text is unavailable, deterministic lexical candidate selection remains
available. Candidate similarity never authorizes dropping evidence or declaring
agreement. Source revisions and exact quotes remain the evidence.

## Budgeting and capability metadata

The active device text runtime currently has a **2,048-token window**, independent
of the selected model's parameter count or advertised training limit. Each
reading job prepares the selected private worker and reads its actual allocated
window from native diagnostics; a missing or invalid report stops preparation.
This does not start inference or contact a server. Context
reserves output and instruction headroom, counts the actual local template and
splits source text into fitting units. Larger source collections therefore do
not require a larger phone context window.

For a selected remote provider, an authorized Context job may perform a bounded,
read-only model-metadata GET. Opening settings does not trigger this probe. It
contains no reader text, does not generate a completion and does not load a
model. The compatible endpoint's exact selected model record can report an
active `max_model_len`. An explicitly selected private compatible server may
also supply the matched llama.cpp default-slot `n_ctx` or LM Studio's loaded
instance `config.context_length`. With multiple eligible loaded instances, the
smallest reported window is used. An advertised model/training limit alone does
not increase the working budget above the conservative **2,048** fallback.

The report separates the adopted budget, active-window evidence, advertised
limit, optional output/input limits, optional tokenizer identity, confidence,
source and observation time. Invalid counts and ambiguous model records are
ignored. Parameter counts, file sizes and model names never imply a window.
Reports have a six-hour cache and a 32-entry bound, scoped to selected
route/model/protocol and direct/Tor mode. Missing metadata uses a five-minute
retry floor instead; retries happen only during an authorized reading job.
An HTTP 400/413 model-request rejection pauses processing with its sources and
receipts intact and invalidates the report for the next request. It does not
automatically resubmit the rejected material or change provider. Model identity
is checked again before binding a report to a processing budget.
Advanced settings provide an explicit
remote window override, constrained by any reported active or advertised limit.
Any reported input limit also constrains the override. Selecting a larger model
does not itself change these budgets, and an active window describes capacity,
not the model's ability to reason faithfully over that capacity.

The configured request window is also distinct from free KV-cache memory at a
particular instant. The attached server currently reports 262,144 tokens through
its selected model record; it does not expose free KV memory or a verified model
architecture there. anti social does not infer either from the model's alias or weight
count. Concurrent load or a server configuration change can still reject a
request that fit an earlier report. Native diagnostics describe this app's
actual allocation; remote reports describe the server's exposed configuration.

Where a matching remote tokenizer is unavailable, UTF-8 byte count plus protocol
headroom conservatively substitutes for token counting. Remote inference has a
1 MiB UTF-8 text-input safety ceiling, a 2 MiB serialized-request ceiling and a
8,192-token output ceiling. These are upper safety bounds, not a promise of
tokenizer parity or that an endpoint accepts the same input. Context's counted
budget reserves the complete response allowance inside the selected active window. Local output is capped
at 512 tokens, decreasing to at most a quarter of a smaller reported window.
No tokenization inference request, automatic paid discovery or
second-provider failover is needed for budget planning.

The native worker can reuse the already processed prefix of the compiled
Context instructions. It snapshots the complete sequence state (including
recurrent state for hybrid models) before any post, comment, attribution or
other reader text enters the model. Token boundaries are checked against the
actual formatted request and aligned to the same prefill batches. The sampler
and live working context are fresh for every request. General text utilities,
altered instructions and arbitrary prompts cannot opt into this cache.

These snapshots stay in RAM: at most four entries, at most **128 MiB** total,
and at most one sixteenth of currently available memory plus the reclaimable
instruction cache. A low-memory report disables and clears it; least recently
used entries are evicted as its allowance shrinks. Worker release on idle,
AI disable or memory pressure frees it. A snapshot that cannot fit is skipped;
processing falls back to ordinary prefill. This avoids repeated instruction
work but does not enlarge the active context window, remove output headroom,
or make a model more capable. Reader source text is never an instruction-cache
entry and no snapshot is persisted to disk.

Published metadata contracts:
[llama.cpp server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md),
[vLLM model metadata](https://docs.vllm.ai/en/latest/api/vllm/entrypoints/openai/models/protocol/),
[LM Studio loaded instances](https://lmstudio.ai/docs/developer/rest/list).
An endpoint can change its configuration after reporting it; refresh, errors and
explicit user settings remain necessary. Metadata reporting is not a benchmark.
The small synthetic model comparison and rejected alternative processing
recipes are documented in [Context evaluation](CONTEXT_EVALUATION.md).

## Model-specific processing

The deterministic `ContextProcessingRouter` selects an executable recipe, rather
than merely enlarging token limits. The reader’s selected model remains the only
text provider. Every recipe uses the same source acquisition, privacy policy,
per-source checkpoints and evidence validation; no model receives tools.

| Recipe | Work assigned to the model | Code-controlled scope |
| --- | --- | --- |
| Focused | A narrow relevance decision for eligible comments, then a separate grounded extraction for useful material. Posts/articles still require a brief. | One source at a time; up to four known findings; 4,096-character source units; compaction groups up to four. |
| Balanced | Review several individually attributed sources together, compare them against bounded known evidence and retain a separate outcome for each source. | Up to four sources per call, 12 known findings, source units up to 65,536 characters and compaction groups up to 64, scaled to the window. |
| Extended | Compare a wider source batch and larger evidence groups with fewer hierarchy boundaries. | Up to eight sources per call, 24 known findings, source units up to 262,144 characters and compaction groups up to 2,048, scaled to the window. |

Response allowances also scale: up to 512 tokens for phone work, 4,096
for Focused or Balanced remote work and 8,192 for Extended work, constrained by any reported
output limit and at most a quarter of the working window. A server’s generation
allowance can include reasoning as well as its visible answer. The native phone
worker remains non-thinking with its existing 512-token maximum and a 32-token
allowance for a narrow relevance vote. Remote votes retain their full response
allowance because their reasoning behavior can be unknown. Generic servers
receive no guessed template or reasoning controls. A reported length stop remains
incomplete work, even if the returned text looks usable.

Actual counted requests, protocol-byte bounds and reserved output can make any
scope smaller. Batched calls need at least an 8,192-token working window and
reserve at least 256 output tokens per admitted source. Even a very large model
with a tight loaded window must use smaller tasks. A large window alone does not
select Extended. Source-unit caps limit individual passages, not how far into a
thread the reader can progress; durable receipts cover subsequent units.

The first automatic recipe is a heuristic: reported models of up to 12 billion
parameters use Focused, 60 billion or more use Extended, and intermediate models
use Balanced. The installed phone runtime always uses Focused. These thresholds
are engineering defaults, not measured universal quality boundaries. Compression
bytes are not substituted for parameter count; a heavily compressed large model
is not relabelled as a smaller model. MoE total parameters are not a claim about
active compute or quality.

Native size comes from the selected loaded runtime’s `llama_model_n_params` and
`llama_model_size`. Published llama.cpp `meta.n_params`/`meta.size` and LM Studio
`params_string`/`size_bytes` are accepted only for the exact selected model or
instance. Rounded LM Studio counts remain reported approximations. Model aliases,
GPU names and file sizes do not invent parameter counts. These observations never
enlarge the active context allocation. Many cloud APIs, and the current Mimir
endpoint, do not publish parameter counts. Their automatic recipe uses individual
source review. **Advanced reading settings → Remote processing** allows Focused,
Balanced or Broader comparisons when the reader knows the model; runtime limits
still apply and the provider never changes. Opening settings makes no requests.

A focused relevance screen cannot discard a question or decide from a missing,
truncated or uncertain background. Invalid votes remain pending. An entirely
interrogative micro-model passage is retained directly after screening, without
asking the model to paraphrase it or compare it with known answers. Other
interrogative quoted findings also keep the exact question and question kind;
it is not published as an asserted answer merely because a model paraphrased it
that way. This deliberately favors retaining an unanswered question over suppressing it
after a weak relevance vote; an irrelevant question can therefore survive this
phone-path guard. Mixed statements and questions still need semantic review. Lexical and
optional local-embedding candidates are interleaved so the small comparison
budget can benefit from both.

On-device profiles and reported models up to 4B select numbered, coherent source
passages. Code binds those IDs to exact prose; the model does not need to write
quotations or author names. Short posts, linked extracts and positively screened
short replies keep their whole text, including adjacent uncertainty and conditions.
Invalid selections remain pending. Selection itself can still miss useful material.

When this exact-source ledger already fits the counted output allowance, code
joins the excerpts with their actual speakers. It does not ask a micro model to
rewrite them. More material still uses the bounded compaction hierarchy, with
source findings available even when a generated overview cannot be accepted.
This short-ledger path preserves source claims; it does not verify their truth.

Batch responses must account for every supplied source exactly once. Every review
is checked before any outcome from that call is committed. An omitted source,
foreign quote, ambiguous citation or malformed response leaves the batch pending;
there is no automatic paid resubmission or provider fallback. Successfully
committed earlier units remain reusable. Plan identities version checkpoints and
summary receipts, so switching recipes cannot reuse a differently scoped review.

An explicit ellipsis inside a model-supplied quotation can be repaired only when
each substantial fragment occurs uniquely and in order in the current source
span. The stored quotation is the complete original interval, including omitted
qualifications. Repeated, reversed, invented, short or oversized matches remain
pending. A literal ellipsis already present in the source stays literal. This
validates evidence provenance, not the model's interpretation of that evidence.

These safeguards establish bookkeeping and bounded execution, not semantic
perfection. Wider comparisons can still misinterpret evidence. Evaluation must
check useful information retained, unsupported assertions and missed additions
for each model/recipe, alongside calls, generated tokens and hardware-specific
latency. Physical-phone timing cannot be inferred from a desktop GPU benchmark.

## Durable processing and compaction

Every source revision is divided using a stable source/profile recipe. A unit's
receipt binds its source identity, revision, offsets, processing profile and
outcome: new signal, repeated information or no signal. Completed receipts are
committed before the source is considered fully reviewed. Interrupted jobs
retain source bodies, continuation cursors, media offsets and unit checkpoints;
an unchanged completed revision is not sent through the model again merely
because its source was refreshed.

Findings retain their supporting source IDs and exact local quotes. For one to
three findings whose labelled paragraphs fit within 900 characters, app code
assembles the brief directly from those findings and their source authors. This
avoids an additional synthesis call and keeps separate contributions separate.
An unsupported internal source alias in such a finding is replaced by its exact
source quote. The underlying extraction can still be wrong; deterministic
assembly does not verify its interpretation.

Larger ledgers use hierarchical compaction: the app groups findings that fit the
active budget, retains each group's leaf evidence and commits reusable summary
receipts. Real speaker labels travel with these groups. Prompts require times,
values and claims to stay attached to their stated events and speakers, and
forbid inventing corrections between separate events. Generated summaries that
expose unsupported internal source aliases are rejected. Source evidence stays
outside generated prose. Explicit numeric and negative qualifications in
corrections have additional mechanical preservation checks. These guards do not
certify semantic completeness; failed compaction leaves the underlying findings
and progress available rather than silently presenting truncated coverage.

An invalid extraction does not become a successful no-signal receipt. Its source
is retained as an explicit model-review coverage gap, while other available
sources can continue. A later request or refresh can retry that material using
its completed unit checkpoints. Coverage distinguishes these unreviewed passages
from genuinely unavailable sources and successfully reviewed comments with no
new information. The controller does not repeatedly retry the same failed
passage inside one processing cycle.

Editing a source invalidates its current revision receipts and findings. An
earlier published brief keeps its married local quote until a new publication is
ready, and is marked as earlier Context while changes are checked. A card split
does not carry an old aggregate brief or another original's evidence into the
new card. A merge can reuse unchanged source receipts. Snapshot revision guards
prevent an old in-flight run from declaring a changed card complete.

The native reader leads with the brief and lets readers inspect findings, local
quoted excerpts and authentic source links. New publications wait behind an
updates-ready control while someone is reading. A partial source status remains
part of coverage instead of replacing readable Context with an error wall.

## Local storage and saved copies

The independent versioned Context database stores source bodies, receipts,
findings, continuations, compactions and publications. Ordinary Context and
temporary media count toward the reader cache allowance. Cleanup removes
unprotected Context whose original cards have left the post cache, and removes
temporary work after completion or eviction. Idle temporary work also expires
after 24 hours during cleanup; an active job's work is excluded. This expiry
applies to intermediate media files, not committed source bodies, receipts or
protected saved evidence. A resumed job may need to fetch its temporary media
again. A low-storage condition pauses new work while retaining committed
progress.

Cleanup captures candidate records before waiting for the separate post-cache
read and deletes only an unchanged, unprotected candidate. A record created,
updated or protected during that wait is retained for a later pass. An old cache
snapshot cannot erase a newly opened Context record or undo new save protection.

Bookmarking any original protects the card's Context. The first protected
publication is an immutable saved baseline with its local supporting evidence;
later refreshes can publish a newer view without overwriting that baseline.
Clearing ordinary cache retains saved Context. Removing the bookmark removes
this protection, so ordinary retention rules can subsequently apply. Context
does not imply that every original attachment has been downloaded: explicit
offline image/video downloads keep their existing separate storage controls.

Model packs are protected explicit downloads, independently removable in AI and
Context media settings. API keys, private model endpoints, AI activation,
capability records and Context automation consent are kept separate from reader
packs and exports. Context's internal database is not currently a portable
interchange/export format.

## Optional automation and privacy

Read-ahead and saved-item maintenance are off by default. Read-ahead follows the
current eligible cards (three by default, configurable from one to ten) and
cancels stale ahead work as reading position changes. Explicit requests take
priority over automatic work. Opting into saved maintenance includes saved posts
whose Context has never been opened. It scans a bounded window of bookmark keys
and processes at most three distinct cards per worker pass, within one shared
automatic time allowance. A local cursor rotates through the library so invalid
or unavailable older copies do not monopolize every pass. Multiple saved editions
of the same merged card share one processing slot.

Bootstrap uses the validated locally captured originals and their merged
editions; cached proper names and the normal presentation rules apply. Existing
newer Context is retained instead of being replaced by an older saved capture.
The original saved post and its immutable Context baseline are not overwritten.
Each card is checked again for a remaining bookmark, AI availability and the
automation opt-in before processing. Background preparation does not open a
reader sheet or create an explicit foreground request.

Repeated unchanged successful checks lengthen each record's next-check delay,
up to one day. Failed or interrupted automatic attempts receive a bounded retry
delay without advancing their successful-check time. Android controls worker
scheduling; the configured interval is not an exact delivery deadline, and a
large library may need several passes to receive its first Context.

Automatic work respects battery level, battery saver, thermal state, storage
and per-pass time allowance (two minutes by default). Heavy OCR/transcription
defaults to charging with unmetered networking, and can be set to manual only or
while browsing. Explicit requests can run outside those automatic conditions,
subject to tool admission and storage checks. Stop retains progress; disabling
AI cancels optional jobs and releases workers. A foreground notification exposes
requested progress and Stop; process interruption can resume durable requested
work after the app recovers. These features require no privileged installation.

Every source, media, model-download, metadata and inference request uses
`NetworkGateway`, preserving filtering, redirect checks, source provenance and
Tor policy. Alternate source routes precede permitted accountless originals;
disabling original fallback prevents that original route. Tor fails closed.
Private model-server HTTP requires the explicit private-server grant and is
unavailable under Tor rather than silently going direct. Remote credentials stay
scoped to the selected service endpoint; metadata and inference do not follow
redirects, reuse source cookies or enter the ordinary content-response observer.

Choosing a cloud or personal server text model sends the selected evidence text
to that selected endpoint for Context processing. Local OCR, speech and text
models avoid that inference upload; fetching public content still contacts its
source through the chosen transport. The app has no Mimir/Bifrost agent bridge.
Model/provider failure never authorizes a silent upload to another provider.
