## Narrow decisions and reusable instructions

A separate finite-label experiment compared passage labels, a single relevance
decision, and a joint relevance/repetition decision. Its grammar restricts the
output to allowed labels or booleans; it does not certify those decisions. On
the initial six-case screen, both the portable native 2B runtime and Prism's
published 2B reference server completed all six single relevance decisions
correctly. The reference server reproduced the broader extraction/novelty
failures, so those failures are not unique to anti social's wrapper. These focused
results alone do not qualify automatic suppression or a replacement protocol.

On the 20 held-out examples, the single relevance protocol matched 19 labels
for each local model. The 2B miss was a relevant Spanish compatibility question;
the 4B miss was a school-bus rerouting update related indirectly to a bridge
closure. Joint relevance/repetition matched 17 labels for 2B and 14 for 4B.
The latter also lost a consequential change from approval to pending. These
are desktop Vulkan synthetic label checks, not app acceptance rates or phone
performance measurements. Separating a decision into a smaller task helped
this sample but did not eliminate useful-information loss.

The selected hosted model's current extraction recipe matched 19 of 20 raw
status labels, also omitting the Spanish question. Manual prose review found
an additional overstatement: a 90°C measurement was called a contradiction of
a safety claim even though the source did not establish a safe temperature
threshold. A matching label is therefore insufficient. Quantity-equivalence
replies can additionally remain pending under the app's stricter changed-number
guard even when a raw model calls them repeated. These results do not support
calling the Context interpretation problem solved.

The first passage-label prompt wrongly treated instructions to a reader as
noise. Practical instructions can be useful evidence. The later relevance
prompt excludes model-directed control instead; the earlier warning failure
must not be attributed solely to the model. The additional
[20-case holdout](../core/src/test/resources/context-evaluation/holdout-v1.json)
covers other subjects, indirect relevance, firsthand evidence, commercial but
useful information, practical instructions, multilingual text, uncertain
evidence, equivalent quantities and changed claims. Expected outcomes require
manual review of retained substance as well as any status label.

Instruction-prefix reuse is a separate deterministic optimization. Twelve
cold/warm comparisons across consistent 2B CPU, 4B CPU and 4B desktop Vulkan
runtime configurations produced byte-identical output for matched requests.
Those trials preserve 32-token prefill boundaries, fresh sampling and complete
sequence state, including hybrid recurrent state. The extraction prefix reused
192 instruction tokens; it contained no post/comment tokens. Snapshot payloads
were about 22.6 MB for 2B and 59.0 MB for 4B. These are measured configurations,
not estimates for every phone or context allocation. Reuse reduces repeated
instruction prefill; it does not improve semantic accuracy or enlarge context.

Complete consistent host builds supersede early exploratory binaries that
mixed newly compiled AVX2 CPU objects with the older portable library set.
Their results are retained but are not production qualification. An additional
experiment omitting unused intermediate output logits did not establish a
meaningful speed improvement and was not adopted. Experimental host GPU times
are not phone performance claims.

Raw evidence for these comparisons is under
`LiberBuild/context-foundation/context-selection/`, including the published
reference-server control, compiler commands, superseded-configuration notice,
prefix parity receipts and held-out role trials. All use synthetic material;
the bench has no reader history or social accounts. No new semantic protocol
is enabled in the app by these experiments.

## Background and server-protocol controls

An additional paired comparison used all 34 original and held-out cases,
presented either with the existing background string or with an explicit
“Subject post” label. The same 2B and 4B weights each returned `signal` for
every case in both formats. Their 23/34 raw status matches simply reflect the
23 cases expected to contain signal; they are not useful accuracy scores.
They still promoted noise and repeated material. In one labelled 2B response,
a Spanish compatibility question became an affirmative compatibility claim,
despite quoting the question exactly. Background labels alone did not solve
these failures. No new semantic recipe was adopted.

The hosted comparison matched 27/34 raw status labels with the existing format
and 29/34 with a subject label. Four and three requests respectively ended at
the completion limit without usable JSON. These counts are not app acceptance
or source-faithfulness scores. Provider variance and the earlier manually
observed unsupported interpretations remain relevant.

A separate two-case control tested the server's `enable_thinking=false`
template hint. Reported reasoning tokens fell to zero, and wall time fell from
6,264 to 301 ms for the noise case and from 1,952 to 204 ms for the Spanish
question. The first decision improved; the second wrongly discarded a useful
question. This is too small and mixed a result to promote the hint. Its
behavior depends on the served template and server version; selected-model
metadata did not identify the architecture, and the optional tokenizer-info
endpoint returned 404. No hidden reasoning text was retained by this control.
See the primary [vLLM reasoning documentation](https://docs.vllm.ai/en/stable/features/reasoning_outputs/)
for the template-specific control. The app's provider protocol remains unchanged.

The shipped source-flow changes address a different, deterministic failure:
fixed short parent strings could hide context and failed to reopen a reply
after its parent changed. Full stored backgrounds, source-native relationships,
complete-input token checks before fallback excerpts, explicit missing-context
flags and a local dependency index
now bind reviews to their actual evidence. They improve input completeness and
receipt validity; they do not establish correct interpretation by a small model.
Raw paired outputs, initial failures, protocol controls and native checks are
retained under `LiberBuild/context-foundation/context-background/`.

## Offline English preparation — 2026-10-19

The 0.35.5 source now prepares an English working view before selected text or
embedding inference, retaining original passages as citation evidence. Actual
offline Spanish fixtures passed with both acquired Bonsai 2B and 4B models on
the isolated API 35 x86_64 device. Both retained the 56 Wh correction, kept the
2021 compatibility question as an unanswered question, cited the Spanish
originals and reused unchanged receipts. These narrow fixtures do not resolve
the earlier English relevance, repetition and indirect-consequence failures.

Qualification exposed and fixed separate mechanical errors: HTML restoration
needed requested token alignments; a stale reader record overwrote the new
processing-policy marker; sorting the cache recipe moved its policy behind the
engine name and prevented complete translated-view cache hits; and the language
gate rejected a short English fixture despite a clear leading detector score.
The latter uses a bounded confidence/margin rule, not an ASCII-language guess.
An interrupted native translation resumes committed passages, and a reopened
database serves its complete English view with translation disabled. Invalid
model initialization returns an error and permits a subsequent valid request
in the same worker rather than aborting the process.

The 2B model lowercased the first character of an otherwise verbatim quote.
Validation now recovers the unique original span only when that initial ASCII
letter's case is the sole difference and the quote has at least 12 characters.
Changed words, internal casing, punctuation, values and ambiguous matches remain
invalid. This is deterministic span recovery, not permission to paraphrase
citations. Original-language quotations remain intact.

Final qualification recorded 1,358 core tests (1,357 pass, one optional
host-native skip) and 72 successful Android executions, including fresh real
2B/4B inference. Native language settings were inspected. Both native ABIs
cross-build with 16 KiB load alignment; these checks do not establish physical
ARM latency, thermal behavior or multilingual translation accuracy. See the
current entry in [validation](../VALIDATION.md). Main preview remains 0.35.3;
0.35.5 was installed only on the isolated test device.

## Translation research beyond the usual shortlist — 2026-10-19

Discovery followed six GitHub metadata queries (56 unique results), four fork
inventories (130 records), package publication metadata, model-file manifests
and linked papers. Counts describe discovery records, not 186 fully audited
projects. Detailed repository metadata, trees, READMEs and available licenses
were followed for 16 valid named repositories, with additional primary model
cards and papers. Fork traversal found Versta.Leanmt; an obscure fxtranslate
mirror led to its upstream publication. Popularity is not a quality criterion.

The most actionable findings distinguish an inference engine from its model
weights. A smaller engine can reuse the already qualified weights, while a
new tiny checkpoint needs its own linguistic evaluation.

A twelve-sentence Spanish diagnostic included negation, uncertainty, questions,
numbers and version identifiers. With the same Mozilla weights, fxtranslate
used approximately 85.5 MiB peak desktop RSS and Leanmt 104.1 MiB, versus 184.7
MiB observed for the existing host reference. Exact output strings matched
10/12 and 9/12 respectively; differing strings included “did not rise” versus
“did not go up,” and Leanmt's “can” versus “may.” String parity is not translation
accuracy. The reference processes a multiline request while candidate probes
request individual sentences, and their kernels differ: these are indicative
footprints, not a controlled throughput ranking or phone-memory guarantee.
No candidate engine has replaced the app's current runtime.

The subsequent integration check acquired German, French, Ukrainian, Arabic
and Japanese packs through the application gateway, then disabled networking
and translated all five. It exposed a low-confidence but fluent English phrase
(“Consult the guide to”: English 0.3699, next candidate 0.117123), a short
Japanese label absent from the detector's top three, and numeric markup that
fragmented Arabic/Japanese grammar. Ignored code tags caused sentence breaks;
ordinary translated spans instead duplicated/misassigned markup during word
alignment. The adopted numeric path leaves values in the sentence and validates
their ordered values/units separately. Opaque links/code still retain their
original tagged identities. The five actual outputs preserved the 56 Wh versus
60 Wh correction, source URL and complete original citation. These are targeted
integration examples, not accuracy measurements for all catalog directions.

A separate frozen [24-case passage collection](../core/src/test/resources/context-evaluation/passage-holdout-v1.json)
tested [two fixed prompts](../core/src/test/resources/context-evaluation/passage-prompts-v1.json)
with acquired compressed 2B/4B weights. The ID selector matched 19/24 and 21/24
useful/not-useful labels, with only 15/24 and 20/24 exact passage selections.
The separate relevance gate matched 21/24 and 20/24 labels. Both approaches
lost useful material; 2B also selected model-directed instructions instead of
the useful passage beside them. Finite IDs prevent invented quote text, not
bad selection. Neither experimental protocol was adopted. A 9B comparison was
intentionally stopped unfinished when the user prioritized translation and KV
implementation; no complete 9B result is claimed. Raw outputs are retained in
`LiberBuild/context-foundation/context-evidence-selection/`.

That audit independently found stale compaction reuse when exact source quotes
changed but generated finding words did not. Summary receipts now bind every
original/reading quote and propagate changed evidence through their ancestors;
the publication shortcut uses the same evidence fingerprint and speaker labels.
Core regressions first reproduced the fault, then verified changed non-leading
quotes, changed late evidence, English working quotes and unchanged-map-order
reuse. A native controller fixture verifies resynthesis after evidence or author
changes while a subsequent unchanged refresh performs no additional review or
summary. These are cache-validity fixes, not semantic-model qualification.

The paper trail supplies concrete design lessons:

- [Sequence-Level Knowledge Distillation](https://aclanthology.org/D16-1139/)
  supports training compact students on teacher outputs; the teacher's work
  happens offline rather than becoming a phone-side inference dependency.
- [Ludicrously Fast NMT](https://aclanthology.org/D19-5632/),
  [Efficient Multilingual NMT](https://aclanthology.org/2021.emnlp-main.674/)
  and [GreenKNIGHT](https://aclanthology.org/2025.findings-emnlp.316/)
  support examining decoder cost, vocabulary filtering, distillation and
  quantized kernels together. Reported speedups belong to each study's setup.
- [MobileNMT](https://aclanthology.org/2023.acl-industry.36/) and
  [Efficient Architectures for Low-Resource MT](https://aclanthology.org/2025.lowresnlp-1.6/)
  make architecture and vocabulary choices relevant alongside parameter count.
- [Too Brittle to Touch](https://arxiv.org/abs/2210.15184) cautions that
  compression/distillation benefits vary by language and training data.
- [TransIns](https://aclanthology.org/2021.emnlp-demo.4/) informs protected
  markup restoration and alignment validation; plain-text fluency alone is
  insufficient when citations, URLs and code must survive.

The recommended next qualification is a same-weight, same-input Android ARM
comparison of Leanmt and fxtranslate with the current runtime, including long
passages, mixed languages, dual vocabularies, URLs, code, numbers, cancellation,
memory pressure and original-citation mapping. Prioritize modern phone kernels
and detect hardware automatically. Do not silently substitute an unqualified
checkpoint because it is small or a host CLI exited successfully.
