# Public preview experiment, October 24, 2026

The requirement is additional accessible information: recover material the
existing routes could not obtain. A 200 response, matching TLS signature or
another copy of an accessible post does not meet it. The native engine remains
opt-in development work, excluded from normal APKs. Release remains 0.38.17.

## Actual observations

An isolated API 35 debug APK used the real NetworkGateway, compiled protection,
platform certificate/hostname validation and new JNI byte engine. Both profiles
retrieved five dated NASA X posts. The desktop profile also retrieved a dated
Facebook post with an image and six Instagram caption/poster previews. This
proves public retrieval through the bridge, not unique value.

The corrected comparison loaded both `darwin-routes.json` and
`public-pathways.json`, performed ordinary account timeline opening, then
compared its result with header-only and native requests. The bundled stack
returned three Facebook posts, six dated Instagram posts through RSS-Bridge
and twelve X posts through FxEmbed. In all three cases every native result was
also obtained by the cheaper header-only request. The native component has
**not demonstrated incremental access over that cheaper route** in these tests.

Some page records fell outside the winning source's first result window. That
does not establish that other existing readers or later pages could not supply
them. This test used one window, a fresh bundled registry, direct transport and
three NASA profiles. It is not exhaustive pagination, an account corpus, live
Tor, quota-renewal or physical-phone qualification. Availability changes.

Earlier attempts remain external for audit. The first used an invalid budget
argument and exercised no baseline. The second omitted the supplemental
registry and requested FEED, excluding existing preview-only readers. Neither
supports unique-access claims. The corrected source/input hashes and results
are in external `evidence/persona-source-build-20261024/android/stack-comparison-v3`.
Private reader backups are separate and never release artifacts.

## Retained engineering work

The source-only build replaces the old combined compatibility archive with
unmodified current primitives. It adds a byte-only JNI bridge, platform trust,
bounded anonymous state, decoded accounting and Gateway-owned sockets. The
final source-built library passed 32 owned wire/response cases on Android API
29; its no-network driver covers 246 admission checks. Eight owned Gateway
cases cover SOCKS domain addressing, cookie scope, mode changes, cancellation,
redirect restrictions, verification ordering and byte/request budgets.

A narrow literal-JSON parser recognizes the observed Instagram Polaris media.
It checks selected-account/shortcode ownership, keeps captions/posters, and
never invents dates or playable videos. Five parser/source-plan cases and ten
existing persona-bank cases also passed. These development checks do not
establish a new release capability.

The full JVM regression passed 2,113 cases with zero failures/errors and one
skip. The Android regression completed fourteen cases with three opt-in skips;
the explicit live comparison ran separately. The isolated native Following
screen was inspected. The laptop's release preview and public APK are unchanged.
An additional default-configuration APK regression passed thirteen cases with
four opt-in skips. ZIP inspection confirms that default APK contains neither
the experimental native library nor its generated metadata/notices.

Full primitive instrumentation exposed the pinned Android runtime's UBSan vptr
problem. A separate valid Base/Derived program reproduced the same failure
without any app/crypto code, matching [NDK issue 2065](https://github.com/android/ndk/issues/2065).
The scoped sanitizer build explicitly excludes that check; intentional heap and
signed-overflow controls still fail as expected. Vptr coverage is unqualified.
That scoped build passed all 32 owned wire/response cases and 246 no-network
admission checks on API 35. The normal library independently passed the same
246 admission checks on API 29. Crypto sources were not patched and no
production checks were disabled to obtain those results.

## Admission decision

Keep the native binary out of normal builds. Preserve its source, reproducible
build and fixtures for a genuine failure case. Investigate the lighter page
route separately, comparing equivalent capabilities against relevant existing
readers before claiming new coverage. Neither route should add requests to a
successful read merely to demonstrate activity. Source refusal/backoff,
privacy, freshness and extraction completeness remain part of admission.
