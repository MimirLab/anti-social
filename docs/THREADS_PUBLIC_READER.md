# Public Threads pages, 0.38.27

The existing accountless-original fallback now retains whole image galleries and
the selected post's supplied replies. **All** and the **Threads** discussion tab
use the ordinary native reader. Retrieved public names enter the existing local
name bank; the same comment records are available to Context. No AI, account,
browser, site script, new native library or extra discovery request is needed.
Darwin's alternatives still precede optional original access. Every read uses
NetworkGateway and the selected Tor policy still fails closed.

## Finding and checking the protocol

The small MIT [toolzerhub/threads-scraper](https://github.com/toolzerhub/threads-scraper)
and the [OpenCLI source investigation](https://github.com/jackwener/OpenCLI/issues/2564)
provided useful field and container references. This is an independent Kotlin
parser; neither collector nor its browser/HTTP runtime is bundled or executed.
Their advertised coverage is not treated as tested anti social coverage.

Two bounded Android Gateway reads on October 25, 2026 obtained a NASA public
profile and an actual post selected from it. The profile contained five dated
posts, including one four-image gallery. The post page contained the selected
root, ten supplied replies and five unrelated recommendations. The source's
reply count was 27, so those ten replies are explicitly a partial snapshot.
Offline replay of those exact responses retains all four gallery images and
the ten replies, excluding all five recommendations. One supplied nested reply
retains its immediate parent. The profile self-reply lacks a nesting level;
its thread grouping survives while its immediate parent remains unknown.

A separate bounded first-continuation experiment used the source-reported
profile query and the fresh page's actual account ID and cursor. It returned
HTTP 403 and stopped. No public continuation, search, complete comment stream,
quota reset or fingerprint-based preview renewal is qualified by this work.
The experimental native browser-persona component remains outside normal APKs.

## Selected content and finite work

Literal `application/json` scripts can supply explicit Relay result-data roots.
Profile records must identify the selected account consistently. Only its
`mediaData.edges[].node.thread_items[].post` connection supplies timeline posts;
related and quoted trees cannot become additional root cards.

For a selected post, its shortcode and account must match the requested and
final page address. A streamed reply patch must repeat the root's exact source
ID; any supplied shortcode, numeric post ID or account must also agree. Only
the patch's `direct_replies`, `pinned_replies` and `self_thread` connections
can donate records. `relatedPosts` never supplies comments. Immediate parents
require the connection's nesting level plus matching reply-to account evidence;
conversation membership can survive when that narrower fact is unavailable.

The earlier single-literal-JSON post form remains readable when its selected
URL, shortcode and author agree but numeric IDs are absent. Missing IDs are
not invented and cannot authorize a separate streamed patch. Contradictory
numeric IDs are rejected. Captions, proper names, source dates, supplied counts,
links, gallery images and playable videos keep their own fields and provenance.
Video duration comes from the attachment, not wording in the caption.

The parser bounds script count, aggregate JSON characters, strict JSON nesting,
visited nodes, streamed records, output posts, galleries and individual fields.
It does no evaluation or follow-up fetching. The first profile window is marked
as a limited timeline, so missing cached frontier posts cannot falsely certify
that the reader has caught up. No cursor or **More replies** action is invented;
an unsupported continuation is rejected before a request. Original access must
remain enabled for this source to appear in the comment plan. An accessible root
without supplied replies does not qualify a healthy COMMENTS result.

Raw public responses, initial failing tests, replay records and Android evidence
are retained externally under `evidence/threads-public-20261025`, outside release
assets. Authored regression fixtures use workshop names and text rather than
embedding live comment bodies in tests. See the dated
